# 姿态保护控制器 · 决策表审计

在把**无序保护规则**下发固件之前，审计遥测布尔变量的**全赋值空间**是否满足：

- **无空洞**：每个布尔赋值都恰好命中一条规则（否则进入未定义状态）；
- **无重叠**：不存在同时命中多条规则的赋值（尤其防止相反动作同时触发）。

支持至多 **64 个稳定变量**、至多 **96 条规则**；条件由标识符、`!`（非）、`&`（与）、`|`（或）、
括号组成（`&&` / `||` 亦可）。

## 裁决方法（非枚举）

裁决核心是 **ROBDD（精简有序二叉决策图）**，见 `src/bdd.js`：

- 变量严格按**标识 ASCII 序**（码点逐字符比较，大写先于小写）排列；
- 边带**补属性**（complement edges），节点经唯一表去重，`ITE` 全记忆化；
- 空洞 `¬(R₁∨…∨Rₙ)`、重叠 `∨ᵢ<ⱼ(Rᵢ∧Rⱼ)`、模型计数（BigInt）全部为符号 BDD 运算；
- 首个反例赋值沿 BDD 按变量序下降取得（优先取 `false`），复杂度 O(变量数)。

**不以枚举、抽样或有限测试替代裁决。**（仓库测试中对 ≤3 变量的全枚举仅用于交叉验证引擎正确性。）

## 审计行为

- 提交后冻结审计结论（服务端保留时间戳、输入快照与结论）；
- **修改任一草稿即清除旧证据**（`PUT /api/drafts` 返回 `evidenceCleared`）；
- 输入错误**一次定位**：非法标识、未知变量、空条件、残缺语法、重复标识、超限等；
- 通过时展示每条规则的**规范节点摘要**（`ite(...)` 前缀式、补边规范化、结构等价必相同）
  与覆盖结论（满足赋值数 / 全空间 `2^N`）。

### 边界结论

| 场景 | 结论 |
|---|---|
| 规则为 `safe` 与 `!safe` | 无空洞、无重叠，通过 |
| 只有 `armed` 条件 | 首个空洞 `armed=false` |
| 不同动作规则相交 | 给出首个赋值，并列出按标识 ASCII 排序的命中规则与动作 |

## 运行（Docker Compose，可配置宿主机端口）

```bash
# 默认宿主机端口 8080
docker compose up --build

# 自定义宿主机端口
HOST_PORT=9090 docker compose up --build
# 或复制 .env.example 为 .env 后修改 HOST_PORT
```

- 操作页面：http://localhost:8080/
- 健康路径：http://localhost:8080/healthz

## 一次性验收（verify）

`verify` 是**执行后退出**的一次性验收服务，围绕上述决策表边界做可观察结果核对，
**退出码即验收结果**（0 通过，非 0 失败）：

```bash
docker compose up --build        # verify 服务执行一次全部核对后退出；app 继续提供页面
docker compose run --rm verify   # 单独再跑一次验收；退出码即结果
```

本地无 Docker 时可直接运行（进程内临时起服务核对，随后退出）：

```bash
npm run check     # 构建检查：全部源文件加载
npm test          # 代码测试（node:test，14 项）
npm run verify    # 一次性验收（52 项：决策表边界 + HTTP/API 冒烟），退出码报告结果
```

## HTTP / API

| 方法 路径 | 说明 |
|---|---|
| `GET /` | 可操作页面 |
| `GET /healthz` | 健康检查 |
| `GET /api/state` | 当前草稿与冻结证据 |
| `PUT /api/drafts` | 替换草稿；任一次修改都会清除旧冻结证据 |
| `POST /api/audit` | 审计当前草稿并冻结结论 |
| `POST /api/reset` | 清空草稿与证据 |

零第三方运行时依赖，仅需 Node ≥ 20。

## 目录

```

src/audit.js    校验编排与决策表裁决
src/server.js   页面/API/健康路径 HTTP 服务
src/verify.js   一次性验收（本地模式或 BASE_URL 远端模式）
test/           node:test 单元测试
web/index.html  操作页面
```
